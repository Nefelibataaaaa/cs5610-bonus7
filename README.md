# CS5610 — Bonus Assignment 7: Pokemon API

A small Node + Hono REST API for managing an in-memory Pokemon collection.

- **Author:** Can Gong
- **Course:** CS 5610 Web Development — Fall 2026
- **Task:** [Bonus Assignment 7 — Pokemon API](https://docs.google.com/document/d/1pndxoiRjGud-ZjL1jlPgpk5PalUSrkJuOzdraObf63Y/edit)
- **Stack:** Node.js, Hono, TypeScript

## Overview

- Pokemon are stored in an in-memory array, preloaded with one Pokemon (Pikachu).
- MongoDB is not used (it was optional in the assignment).
- All endpoints live under `/api/pokemon`.
- Data resets whenever the server restarts.

## Pokemon model

| Field   | Type   |
| ------- | ------ |
| id      | number |
| name    | string |
| species | string |
| health  | number |
| level   | number |
| owner   | string |

## Endpoints

| Method | Path                 | Description                                                                 |
| ------ | -------------------- | --------------------------------------------------------------------------- |
| GET    | `/api/pokemon`       | Retrieve all Pokemon                                                        |
| GET    | `/api/pokemon/{id}`  | Retrieve a specific Pokemon                                                 |
| POST   | `/api/pokemon`       | Create a Pokemon; the server generates `id`, `health`, and `level`           |
| PATCH  | `/api/pokemon/{id}`  | Update only the provided fields                                             |
| DELETE | `/api/pokemon/{id}`  | Delete a Pokemon from memory                                                |

### Creation behavior

- `id` is randomly generated (unique among existing Pokemon).
- `health` (50–99) and `level` (1–20) are randomly generated by default.
  If valid numbers are explicitly provided, those values are used.
- If `name` is absent, it defaults to `species`.

### Validation

- `species` and `owner` must be non-empty strings (never falsy).
- `id` must not be supplied in a `POST` request.
- `health` and `level`, if provided, must be numbers.
- `name`, if provided, must be a string.
- Request bodies must be JSON objects.

## Getting started

```bash
npm install
npm run dev
```

The server listens on **http://localhost:3000**.

Other scripts:

```bash
npm start       # run once (no watch)
npm run typecheck
```

## Example requests

```bash
# List all Pokemon
curl http://localhost:3000/api/pokemon

# Get one Pokemon
curl http://localhost:3000/api/pokemon/1

# Create a Pokemon (id, health, level are generated)
curl -X POST http://localhost:3000/api/pokemon \
  -H "Content-Type: application/json" \
  -d '{"species":"Charmander","owner":"Gary"}'

# Update fields
curl -X PATCH http://localhost:3000/api/pokemon/2 \
  -H "Content-Type: application/json" \
  -d '{"level":50}'

# Delete a Pokemon
curl -X DELETE http://localhost:3000/api/pokemon/2
```

## Notes

- Responses use a consistent shape: `{ "success": true, "data": ... }` on success and `{ "success": false, "error": "..." }` on failure.
